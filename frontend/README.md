# 多语言内容制作平台

围绕“段落身份 + 译文对应关系”构建的正文/译文编辑器。

## 核心规则

- **稳定段落身份**：正文段、译文段、关联各有独立 ID，文档顺序与身份分离。
- **移动不丢译文**：上移/下移正文只调整顺序，ID 与关联保持不变，重复句子不会错配。
- **失效粒度到段**：正文实质改写（规范化空白后仍不同）时，仅该段名下状态为
  `ok` 的关联转为 `needs_review`；仅空白差异不失效；其他段落完全不受影响。
- **拆分**：原段保留前段内容与身份（旧关联不变），后段是全新 ID，不自动继承
  任何旧译文，避免旧译文被误当成新内容的译文。
- **合并**：被并段删除，其译文关联迁移到新段并标待核对，天然形成一对多；
  “调整对应”模式可任意建立/解除关联，因此也支持多对一。
- **撤销/重做**：每次操作整体入栈，撤销拆分或合并会恢复被删段落的原文与关联。
- **保存重开**：保存写入 `localStorage`（`mlcp.doc.v1`），重开按 ID 完整恢复。
- **导出/导入**：JSON 中携带全部 ID 与关联，导入即恢复，用于跨环境核对。

## 操作方式

- 正文卡片：上移/下移、拆分（两个编辑框分别填写两段内容）、勾选多段后点“合并勾选段”。
- “调整对应…”：进入关联模式后点击译文卡片即可建立对应（默认待核对），可在
  正文卡片中解除已有对应。
- 待核对关联显示橙色标记，可单条“核对无误”或“全部核对通过”。
- 顶部：撤销、重做、保存、导出/导入 JSON。

## 开发

```bash
npm install
npm run dev        # 本地开发
npm run test       # vitest 单元测试
npm run typecheck  # tsc 严格检查
npm run build      # 生产构建
```

测试覆盖：含中文标题与重复句子的文稿上连续拆分、合并、移位、实质改写、
撤销、保存重开与导出往返，断言无丢段、无错配、旧译文不会绑定到新段落。

## 关键文件

- `src/types.ts`：`SourceSegment / TargetSegment / SegmentLink` 数据结构。
- `src/model/doc.ts`：纯函数文档操作（移动、编辑、拆分、合并、关联、导入导出）。
- `src/model/text.ts`：实质改写判定（空白归一化）。
- `src/store.ts`：zustand 状态、撤销/重做栈、保存。
- `src/App.tsx`：双栏编辑界面。
